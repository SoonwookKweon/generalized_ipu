# 아키텍처 개요 (Architecture Overview)

본 문서는 `generalized-ipu`의 패키지 구성, 자료 흐름, 계층 간 의존 관계를 서술한다. 모든 용어는 `docs/01_용어와_정의.md`의 정의를 따른다.

---

## 1. 라이브러리의 목적

`generalized-ipu`는 표본 미시 자료의 각 기본 단위에 가중치를 부여하여, 가중합이 외부에서 주어진 다수의 집계 제약을 동시에 충족하도록 조정하는 반복 비례 갱신(Iterative Proportional Updating, IPU) 라이브러리이다. 기존 `pyipu`가 가지고 있던 다음 여섯 가지 제약을 해소하는 것이 설계 목표이다.

| 기존 한계 | 본 라이브러리의 확장 |
| --- | --- |
| 가구와 개인의 2계층 고정 | 임의의 $N$계층 트리 |
| 고정 스칼라 목표값만 허용 | 구간 목표 $[L_k, U_k]$ 수용 |
| 1차원 또는 2차원 주변표만 허용 | $N$차원 교차표 텐서 수용 |
| 단일 범주 세분화 수준 전제 | 소범주와 대범주의 혼재 수용 |
| 주변표의 결측 셀을 처리하지 못함 | 균형식으로부터 목표 구간을 연역 |
| 상위 계층 개체 수를 셀 수 없음 | 분수 귀속으로 다가구주택 구조를 수용 |

---

## 2. 계층 구조

라이브러리는 다음 네 개의 논리 계층으로 구성된다. 상위 계층은 하위 계층에만 의존하며, 역방향 의존은 허용하지 않는다.

```
┌─────────────────────────────────────────────────────────┐
│  응용 계층    io/            자료 적재, 결과 내보내기        │
├─────────────────────────────────────────────────────────┤
│  조율 계층    engine/        반복 루프 주도, 종료 판정       │
│              diagnostics/   반복 이력 수집, 진단 보고서     │
├─────────────────────────────────────────────────────────┤
│  연산 계층    matrix/        속성 행렬 구축, 희소 연산 커널  │
├─────────────────────────────────────────────────────────┤
│  정의 계층    hierarchy/     계층 트리, 범주 위계           │
│              constraints/   제약 객체, 목표값, 영 셀 처리   │
└─────────────────────────────────────────────────────────┘
```

의존 규칙은 다음과 같다.

- `hierarchy`와 `constraints`는 다른 내부 패키지에 의존하지 않는다.
- `matrix`는 `hierarchy`에 의존한다.
- `engine`은 `matrix`, `constraints`, `diagnostics`에 의존한다. 갱신 비율의 규칙은 `constraints`가 정의하므로 엔진이 이를 복제하지 않는다.
- `diagnostics`는 배열과 표만 입력으로 받으며 어떤 내부 패키지에도 의존하지 않는다.
- `io`는 최상위 조립 지점으로서 모든 패키지를 사용할 수 있다.

## 3. 자료 흐름

전체 파이프라인은 준비 단계와 반복 단계로 나뉜다. 준비 단계는 1회 실행되고, 반복 단계는 수렴하거나 최대 반복에 도달할 때까지 되풀이된다.

```
[준비 단계]

  계층별 원본 자료          제약표(스칼라/구간/텐서)      도메인 규칙
        │                          │                        │
        ▼                          ▼                        ▼
   HierarchyTree            ConstraintRegistry      LogicalRuleParser
   (무결성 검증)             (목표 구간 정규화)        (유효 마스크 산출)
        │                          │                        │
        └──────────┬───────────────┴────────────────────────┘
                   ▼
        UnifiedSparseMatrixBuilder
        - 계층별 속성을 기본 계층 좌표계로 집계
        - N차원 텐서를 제약 열로 평탄화
        - 대범주 매핑 행렬 결합
        - 구조적 영 제약 열 색인 제외
        - 표본 영 제약 열에 epsilon 주입
                   │
                   ▼
        속성 행렬 A (n x K, CSR)  +  목표 구간 (L, U)


[반복 단계]  t = 0, 1, 2, ...

   w^(t) ──► S = A^T w^(t)                      (가중합 산출)
              │
              ▼
           v_k = max(L_k - S_k, S_k - U_k, 0)   (구간 위반량)
              │
              ├──► 수렴 판정 ──► [충족] 종료
              │
              ▼
           r_k = 구간별 갱신 비율
              │
              ▼
           w~ = w^(t) * (1 + eta * A(r-1) / rowsum(A))   (동시 갱신)
              │
              ▼
           w^(t+1) = 배율 제한 및 가중치 하한 적용
              │
              └──► ConvergenceTracker 에 회차 이력 기록


[종료 단계]

   최종 가중치 w  ──► FitReportGenerator      (제약 열별 적합도)
                  ├─► WeightDistributionAnalyzer (가중치 분포 진단)
                  └─► DatasetExporter           (원자료 역결합 및 저장)
```

## 4. 핵심 설계 결정

### 4.1 기본 단위 좌표계로의 통일

$N$개 계층, $N$차원 교차표, 범주 위계라는 세 가지 확장 요건은 모두 "제약의 종류가 늘어난다"는 하나의 문제로 환원된다. 라이브러리는 이 세 요건을 각각 다른 방식으로 처리하지 않고, 전부 기본 단위 좌표계 위의 속성 행렬 $A$의 열로 변환한다. 그 결과 반복 루프는 제약의 출처를 알 필요가 없으며, $\mathbf{S} = A^{\top}\mathbf{w}$라는 단일 연산만 수행한다.

이 결정의 대가는 속성 행렬의 열 수 $K$가 커진다는 점이며, 이는 희소 표현으로 흡수한다.

### 4.2 희소 행렬(CSR)의 채택

다차원 결합 제약과 계층 확장이 동시에 적용되면 제약 열의 수가 조합적으로 증가한다. 개별 기본 단위는 수천 개의 결합 범주 중 극히 일부에만 속하므로 속성 행렬의 대부분이 0이 된다.

관계형 장형(longform) 표는 `(base_id, constraint_id, count)` 세 값을 행마다 저장하므로 식별자 오버헤드가 크고, 반복마다 결합(join)과 집단화(groupby)를 실행하여 해시 색인 병목을 유발한다. CSR(Compressed Sparse Row) 형식은 비영 값과 색인 포인터만 연속 메모리 버퍼에 저장하므로 메모리 사용량이 작고, 초기 1회 구축 이후 재할당 없이 $O(\mathrm{nnz}(A))$ 복잡도의 희소 행렬-벡터 곱만 반복한다.

### 4.3 목표의 구간 일원화

스칼라 목표를 퇴화 구간으로 취급함으로써 제약 처리 경로를 하나로 유지한다. 그 결과 스칼라 목표와 구간 목표를 섞어 입력해도 반복 루프의 분기가 늘지 않는다.

### 4.4 구조적 영과 표본 영의 분리 처리

두 유형의 0을 동일하게 다루면 불가능한 조합에 가중치가 배분되거나, 실재하는 범주가 영구히 0으로 고정된다. 라이브러리는 구조적 영을 속성 행렬 구축 단계에서 색인 자체로부터 제외하고, 표본 영에만 $\varepsilon$ 평활을 적용하여 두 오류를 모두 차단한다.

### 4.5 결측 셀의 대치가 아닌 구간화

주변표의 결측 셀을 점 추정으로 채우면 근거 없는 정보가 목표에 주입되고, 그 목표는 이후 퇴화 구간으로서 다른 제약과 동등한 강도로 반복 루프에 작용한다. 라이브러리는 대치 대신 구간화를 택한다. 결측 셀에는 균형식으로부터 연역한 구간을 부여하며, 연역할 근거가 없으면 $[0, \infty)$로 두어 그 셀이 아무런 정보를 주장하지 않게 한다.

이 결정은 4.3의 구간 일원화가 있었기에 가능하다. 목표가 이미 구간으로 표현되므로 결측 셀을 위한 별도의 자료형이나 처리 경로가 필요하지 않다.

균형식은 부수적으로 목표 정합성의 사전 검사 역할도 한다. 구간을 좁히는 도중 하한이 상한을 넘어서면 주어진 제약표들이 서로 모순된다는 뜻이며, 이는 반복을 시작하기 전에 판정된다.

### 4.6 상위 계층 개체 수의 분수 귀속

상위 계층의 속성을 기본 단위로 옮기는 기정 경로는 방송이다. 방송은 수량 속성에는 적합하지만 개체 수에는 적합하지 않다. 값이 1인 열을 방송하면 그 열의 가중합이 상위 계층 개체 수가 아니라 기본 단위 수가 되기 때문이다.

거처 계층에 가구 계층이 매달린 다가구주택 구조에서 "거처 수"를 제약하려면 소속 가구 $m$개에 각각 $1/m$을 부여해야 한다. 라이브러리는 이를 별도의 계층 유형이나 특례 경로가 아니라 `ShareBlock`이라는 하나의 블록 명세로 흡수한다. 4.1의 결정에 따라 이 블록도 결국 속성 행렬의 열이 되므로 반복 루프는 변경되지 않는다.

## 6. 사용 예시

### 6.1 기본 구성

세 계층(지역, 가구, 개인) 자료에 가구 단위 제약과 개인 단위 결합 분포 제약을 함께 부여하는 최소 예시이다.

```python
import numpy as np
from generalized_ipu import (
    BoundChecker, ConstraintRegistry, CrossTabBlock, ColumnBlock,
    FitReportGenerator, GeneralizedIPUEngine, HierarchyTree,
    TensorTarget, UnifiedSparseMatrixBuilder,
)

tree = HierarchyTree(base_level="household")
tree.add_level("region", regions, primary_key="region_id")
tree.add_level("household", households, primary_key="hh_id",
               parent_key="region_id", parent_level="region")
tree.add_level("person", persons, primary_key="person_id",
               parent_key="hh_id", parent_level="household")

dims = {"age_group": ["child", "adult"], "sex": ["M", "F"]}
attribute = UnifiedSparseMatrixBuilder(tree).build([
    ColumnBlock(name="hh_car", level="household", cols=["car"]),
    CrossTabBlock(name="person_age_sex", level="person", dims=dims),
])

registry = ConstraintRegistry()
registry.register(BoundChecker("hh_car", "household", {"car": (350.0, 450.0)}))
registry.register(TensorTarget("person_age_sex", "person", dims,
                               np.array([[150.0, 150.0], [400.0, 400.0]])))

result = GeneralizedIPUEngine.from_registry(
    attribute.matrix, registry, relative_gap=0.02, max_iterations=300
).fit()

print(result.termination_reason, result.n_iterations)
report = FitReportGenerator.generate_report(
    result.weighted_sums, *registry.bounds(),
    column_names=attribute.column_names, column_owners=registry.column_owners,
)
```

### 6.2 다가구주택과 $n$인가구 제약

거처, 가구, 가구원의 세 계층에서 기본 계층을 가구로 둔 구성이다. 거처 수 제약은 `ShareBlock`으로, 가구 규모별 가구 수 제약은 파생한 계급 열의 `CrossTabBlock`으로 만든다.

```python
from generalized_ipu import (
    AggregationMapper, BoundChecker, ConstraintRegistry, CrossTabBlock,
    GeneralizedIPUEngine, HierarchyTree, ShareBlock, UnifiedSparseMatrixBuilder,
)

tree = HierarchyTree(base_level="household")
tree.add_level("dwelling", dwellings, primary_key="dwelling_id")
tree.add_level("household", households, primary_key="hh_id",
               parent_key="dwelling_id", parent_level="dwelling")
tree.add_level("person", persons, primary_key="person_id",
               parent_key="hh_id", parent_level="household")

# n인가구: 가구원 수를 세어 계급 열로 파생시킨다.
sizes = AggregationMapper.descendant_count_to_base(tree, "person")
tree.nodes["household"].data["size_class"] = (
    AggregationMapper.size_class_labels(sizes, boundaries=(1, 2, 3, 4)).to_numpy()
)

attribute = UnifiedSparseMatrixBuilder(tree).build([
    # 다가구주택: 거처 1호를 소속 가구 수로 나누어 한 번만 계상한다.
    ShareBlock(name="dwelling_class", level="dwelling",
               dims={"hh_class": ["1", "2", "3+"]}),
    CrossTabBlock(name="hh_size", level="household",
                  dims={"size_class": ["1", "2", "3", "4+"]}),
])
```

두 제약표는 서로 독립이 아니다. 가구 수 계급별 거처 수 $D_m$의 가중 합계 $\sum_m m D_m$은 총 가구 수와 같아야 하고, $n$인가구 수 $H_n$의 가중 합계 $\sum_n n H_n$은 총 가구원 수와 같아야 한다. 두 관계 모두 `MissingMarginEstimator`의 균형식으로 표현되므로, 어느 한 표에 결측이 있으면 다른 표의 관측값이 그 구간을 좁힌다.

### 6.3 결측 주변표의 구간화

```python
from generalized_ipu import MissingMarginEstimator, balance_from_classes

# 2인가구와 3인가구 수가 공표되지 않았고, 총 가구 수와 총 가구원 수는 알려져 있다.
# 두 균형식이 함께 작용하여 두 결측 셀이 각각 90호와 60호로 확정된다.
estimator = MissingMarginEstimator({"1": 40.0, "2": None, "3": None, "4+": 10.0})
estimator.add_balance("households", 200.0)
estimator.add_balance(
    "persons", 446.0,
    balance_from_classes(["1", "2", "3", "4+"], [1.0, 2.0, 3.0, 4.6]),
)

constraint = estimator.to_constraint("hh_size", "household")
print(estimator.to_frame())
```

`4+` 계급의 대표값 4.6은 추정량이므로, 그 오차는 균형식의 총계를 구간으로 주어 흡수한다. 셀들의 합이 총계와 같아야 한다는 결합 조건까지 부과하려면 `balance_hierarchy`가 반환한 위계로 `CoarseBlock`을 추가하고 `balance_constraint`를 함께 등록한다.
